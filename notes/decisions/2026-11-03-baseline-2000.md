# 기준선: 다이어터 1,000명 + 운동 초보자 1,000명

| 항목 | 값 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | 결정 |

## 배경

PR #6을 배포해 운동 초보자 1,000명을 더했다(2026-11-02 15:22 KST). 같은 배포로 PR #4·#5도 처음 들어가, 다이어터에
체중 기록·식사 수정·간식·운동 기록이 더해졌다. 이후 개선 전후를 비교할 수 있게 사용자 수, 트래픽, 페르소나와 세션,
API별 응답 시간, 서버 자원을 한곳에 남긴다.

용어는 [1,000명 기준선](2026-11-02-baseline-1000.md)과 같다. TPS는 초당 HTTP 요청 수(= RPS), 세션/s는 초당 끝난
업무 세션 수, DB TPS는 초당 MySQL 커밋 수다.

## 측정 구간과 트래픽

| 항목 | 값 |
|---|---|
| 구간 | 2026-11-02 15:23 → 11-03 09:10 KST, 17.8시간. 발생기 설정이 한 번도 바뀌지 않은 구간이다 |
| 발생기 코드 | `6170b58` (PR #6 병합) |
| 대상 | 운영 backend(`kkugi-backend-lightsail`). 발생기는 관측 서버(`kkugi-observability-lightsail`)에서 실행 |
| 실행기 | Locust User 20개. Worker 4개에 5개씩 |
| HTTP 요청 | 16,400건. 평균 0.253 TPS, 1시간 최대 0.902 TPS (18시) |
| 업무 세션 | 2,557건. 평균 0.039 세션/s. 세션당 요청 6.41개 |
| 실패 | HTTP 요청·세션 모두 0건. 놓친 세션 0건 |

| 페르소나 | 계정 번호 | 경로 (프라이빗 / 공인) | 이 구간에 요청을 보낸 계정 | 이 구간에 새로 가입한 계정 |
|---|---|---|---:|---:|
| 다이어터 | 0-999 | 950 / 50 | 730 | 0 |
| 운동 초보자 | 1,000-1,999 | 950 / 50 | 703 | 703 |
| 합계 | | | **1,433** | 703 |

- 요청을 보낸 계정 수는 발생기의 일정 규칙을 코드로 재현해 셌다. 재현한 세션 수가 Locust 기록과 세션 종류마다 같았다.
  유일한 차이는 `dieter_view` 1건으로, 구간 끝(09:09:48 기록)에 실행 중이던 세션이다.
- 다이어터 1,000명은 이전 배포부터 가입·온보딩한 상태다. 운동 초보자는 이 구간의 첫 세션에서 가입·온보딩했다.

   ```bash
   ssh kkugi-obs 'docker exec kkugi-loadgen-master-1 cat /app/stats/<이름>_stats_history.csv' > history.csv
   ```

2. 구간을 정해 요약한다. `--to`는 그 시각 이전의 마지막 기록까지 센다.

   ```bash
   python tools/stats_summary.py hourly history.csv --from '2026-11-02 15:23' --to '2026-11-03 09:10'
   ```

   ```bash
   python tools/stats_summary.py apis history.csv --to '2026-11-03 09:10'
   ```

   API별 클라이언트 값은 history CSV에서 `--to` 시각 이전 마지막 기록의 누적값(요청 수, 실패, 평균, 중앙값, 최대,
   응답 크기)을 읽는다. Master가 시작한 시각부터의 누적이므로 구간 시작은 Master 시작 시각이다. `_stats.csv`를 넣으면
   백분위까지 나오지만 지금까지의 누적값이라 구간을 자를 수 없다.

3. 서버 쪽 값은 관측 서버의 Prometheus(`localhost:9090`)에서 구간 끝 시각(`time`)과 구간 길이로 조회한다.

   ```text
   API별 요청 수  sum by (method,uri)(increase(http_server_requests_seconds_count{synthetic="true"}[17h47m]))
   API별 p95      histogram_quantile(0.95, sum by (le,method,uri)(increase(http_server_requests_seconds_bucket{synthetic="true"}[17h47m])))
   DB 커밋        sum(increase(mysql_global_status_commands_total{command="commit"}[17h47m]))
   시간별 DB TPS  sum(rate(mysql_global_status_commands_total{command="commit"}[1h]))
   커넥션 대기    max_over_time(hikaricp_connections_pending[17h47m])
   ```

4. 서버 CPU와 버스트는 Lightsail 지표로 본다. 명령은 README의 "서버 운영"에 있다.
