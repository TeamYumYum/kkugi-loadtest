# 기준선: 다이어터 1,000명 + 운동 초보자 1,000명

| 항목 | 값 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | 결정 |

## 배경

PR #6을 배포해 운동 초보자 1,000명을 더했다(2026-11-02 15:22 KST). 같은 배포로 PR #4·#5도 처음 들어가, 다이어터에
체중 기록·식사 수정·간식·운동 기록이 더해졌다. 이후 개선 전후를 비교할 수 있게 사용자 구성, 계획 트래픽, 실측
처리량, API별 응답 시간, 서버 자원을 한곳에 남긴다.

용어는 [1,000명 기준선](2026-11-02-baseline-1000.md)과 같다. TPS는 초당 HTTP 요청 수(= RPS), 세션/s는 초당 끝난
업무 세션 수, DB TPS는 초당 MySQL 커밋 수다.

  많은 세션이 더해졌기 때문으로 보인다(추정). 15-16시가 2배 안팎인 것은 새 계정의 가입·온보딩 때문으로 보인다(추정).
- 자정 급증이 이틀 연속 나왔다. 1분 DB TPS가 11-02 00:01에 55.6, 11-03 00:01-00:02에 48.4·71.0이다. 같은 시각의
  HTTP 요청은 평시와 같았다. backend의 자정 배치 작업으로 보인다(확인 필요).

## 비교에 쓸 핵심 지표

개선 전후를 비교할 때는 아래 값을 같은 방법으로 다시 잰다. 응답 시간은 배율과 계정 수의 영향을 적게 받으므로 계정
수가 달라도 비교할 수 있고, 처리량은 같은 계정 수·배율·시간대끼리 비교한다.

| 지표 | 지금 값 | 왜 보는가 |
|---|---|---|
| 피크 시간대 TPS (12시, 18시) | 배율 0.5에서 18시 0.90 | 부하 규모. 계정 수를 늘린 효과를 확인한다 |
| `GET /daily-summaries/{date}` p95 | 클라이언트 150ms, 서버 145ms | 가장 많이 부르고 가장 느린 조회. 요약 계산 쿼리 개선의 대상이다 |
| `POST /workout-sessions` p95 | 140ms | 가장 느린 쓰기 |
| `POST /routines`, `PUT /weekly-workout-goal/me` p95 | 110ms, 130ms | 첫 운동 준비 요청. 계정이 늘 때 몰린다 |
| 요청당 DB 커밋 (18시) | 1.48 | 쓰기 구조가 바뀌면 달라진다 |
| HTTP 실패율 | 0% | 거버너 기준은 2% |
| `missed` 세션 | 0건 | 실행기가 모자라면 늘어난다 |
| `start_delay` p95 | 990ms | 실행기 여유 |
| 공인 경로 인증 p50 차이 | +약 180ms | 경로 구성이 바뀌면 달라진다 |
| 커넥션 풀 최대 사용 / 대기 | 2/10, 0 | DB 연결이 병목이 되는지 |
| backend CPU 최대 | 17.4% | 서버 여유 |
| 자정 DB TPS 최대 (1분) | 71.0 | 배치 작업의 규모. 회원 수와 함께 늘어나는지 본다 |

## 다시 재는 방법

1. Master의 CSV를 내려받는다. 이름에 Master 시작 시각이 붙는다.

   ```bash
   ssh kkugi-obs 'docker exec kkugi-loadgen-master-1 ls -t /app/stats'
   ssh kkugi-obs 'docker exec kkugi-loadgen-master-1 cat /app/stats/<이름>_stats.csv' > stats.csv
   ssh kkugi-obs 'docker exec kkugi-loadgen-master-1 cat /app/stats/<이름>_stats_history.csv' > history.csv
   ```

2. 표로 요약한다. `_stats.csv`는 Master가 시작한 뒤의 누적값이므로, 구간을 나눠 보려면 `hourly`의 `--from`, `--to`를 쓴다.

   ```bash
   python tools/stats_summary.py hourly history.csv --from '2026-11-03 09:11'
   python tools/stats_summary.py apis stats.csv
   ```

3. 서버 쪽 값은 관측 서버의 Prometheus(`localhost:9090`)에서 조회한다.

   ```text
   DB TPS        sum(rate(mysql_global_status_commands_total{command="commit"}[1h]))
   backend TPS   sum(rate(http_server_requests_seconds_count{synthetic="true"}[1h]))
   API별 p95     histogram_quantile(0.95, sum by (le,method,uri)(rate(http_server_requests_seconds_bucket{synthetic="true"}[18h])))
   커넥션 대기   max_over_time(hikaricp_connections_pending[18h])
   ```

4. 서버 CPU와 버스트는 Lightsail 지표로 본다. 명령은 README의 "서버 운영"에 있다.
