# 관측은 이미 있는 것으로 시작한다

| 항목 | 값 |
|---|---|
| 날짜 | 2026-10-29 |
| 상태 | 결정 |
| 대체 | [시작 규모와 관측 서버 부담](2026-10-29-start-scale-and-load.md)의 "수집 쪽 작업은 서비스 저장소에 맡긴다"를 "필요할 때만"으로 낮춘다 |

## 결정

- **서버 CPU와 크레딧은 Lightsail 콘솔이나 AWS CLI로 본다.** 서비스 저장소에 서버 지표 수집을 더하지 않는다. 컨테이너별 사용량은 서버에서 `docker stats`로 본다.
- **서비스 저장소의 수집 작업(추적·로그 샘플링, 서버 지표 수집, 발생기 지표 수집)은 모두 선택이다.** 추적·로그 샘플링은 실측에서 수집이 버티지 못할 때만 한다.
- **발생기의 Prometheus `/metrics`는 보류한다.** 인공 요청의 양·응답 시간·오류는 backend 지표의 `synthetic` 태그로 이미 Grafana에서 보인다. 발생기에서만 보이는 클라이언트 응답 시간과 세션 결과는 실측 기간에 Locust의 CSV 통계 기록(`--csv-full-history`)으로 본다.
- **거버너는 Master 안의 Locust 통계를 직접 읽는다.** Prometheus에 기대지 않는다.
- **탈퇴된 계정의 이메일 번호는 `generation × 1,000,000 + 계정 번호`다.** 발생기는 탈퇴 API를 부르지 않는다. 바깥에서 인공 계정이 탈퇴되었을 때를 대비한 처리다.
- **상태 DB 형식은 변환 코드 없이 바꾼다.** 상태 DB(`state/accounts.db`, Worker마다 하나)는 계정별 토큰·회원 ID·온보딩 여부를 저장하는 SQLite 파일이다. 아직 운영에서 쓴 적이 없으므로, 옛 형식 파일을 만나면 지우라는 안내와 함께 시작하지 않는다.
