# notes

설계 결정과 구현 계획을 남기는 곳이다. 저장소에 함께 올린다.

다른 사람이나 에이전트에게 맡길 작업 지시서와 인계 문서는 여기에 두지 않는다.

| 위치 | 내용 | 쓰는 방식 |
|---|---|---|
| `decisions/` | 결정 기록. 무엇을 왜 정했는지 | 결정 하나(또는 한 번의 논의)마다 파일 하나. 한번 쓴 결정은 고치지 않고, 바뀌면 새 기록을 쓴다 |
| `plan.md` | 지금의 구현 계획 | 계속 고쳐 쓴다. 숫자와 근거는 결정 기록을 가리키기만 한다 |

이 메모는 원문을 대신하지 않는다. 코드·설정·README와 어긋나면 그쪽이 맞다. 어긋난 메모는 고치기보다 지운다.

## 결정 기록 쓰는 법

파일 이름은 `decisions/{YYYY-MM-DD}-{주제}.md`다. 아래 틀을 쓰고, 해당 없는 절은 지운다.

```markdown
# {주제}

| 항목 | 값 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 상태 | 결정 / 일부 미결 / 대체됨(→ 새 기록 파일) |

## 배경
무엇이 문제였는지.

## 결정
정한 것. 사용자가 정한 값과 가정으로 채운 값을 표시해 구분한다.

## 근거
왜 그렇게 정했는지. 버린 선택지와 버린 이유.

## 결과
이 결정에서 나오는 숫자와 영향. 계산 가정을 함께 적는다.

## 미결
아직 정하지 않은 것. 정해지면 새 기록을 쓰거나 이 절을 갱신한다.
```

- 결정이 바뀌면 옛 기록의 상태를 `대체됨(→ 새 파일)`로만 바꾸고 본문은 그대로 둔다.
- 확인하지 못한 것은 "확인 필요"로 적는다.
