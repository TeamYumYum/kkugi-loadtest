### 결과를 읽을 때

- 단일 조회 시간은 로컬 HTTP 요청, 응답 본문 수신과 JSON 파싱을 포함한다. 동시·혼합의 k6 시간은 요청 전송부터 응답 수신까지이며 TCP 연결 초기화를 별도 지표로 기록한다.
- MySQL 문장 시간은 서버의 Performance Schema에서 얻었다. `SELECT`와 세션 설정·커밋을 집계했다. 스키마에 귀속된 문장만 포착된다. Hikari 평균 획득 시간은 풀 대기와 바쁜 커넥션이 없는 상태에서의 획득 비용을 포함한다. 순차 조회 10건씩을 묶고 릴레이 또는 잠금 SQL이 감지된 구간은 SQL·Hikari 집계에서 뺐다.
- 두 버전에 같은 저장 본문을 보냈다. 전환 전에는 조회가 지급을 확인하고 조건에 따라 쓰기를 한다. 전환 후 조회는 기존 지급 결과를 읽고, 저장 응답의 `newBadges`는 해당 기록의 첫 기록 뱃지를 돌려준다. 누적 뱃지는 이벤트로 처리한다. 부하 발생기는 성공 상태와 응답 시간을 비교한다.
- 초기 지급을 마친 32계정과 온보딩만 한 32계정을 섞었다. 순차 조회는 예열을 거친 반복 경로를 잰다. 운동 저장의 분당 약 20건은 기록이 있던 계정으로 실행됐다. 하루 활동 전체, AI 배치, 전환 후 첫 시작 백필은 이 로컬 비교 범위 밖이다.
- 단일 요청에서 실제 SQL 왕복 시간은 `SELECT 1`로 별도 관측했다. 프록시의 방향별 설정값과 Windows 호스트를 경유한 측정값을 따로 기록했다. 로컬 절대 시간의 적용 범위는 이 PC와 데이터 구성이다.
