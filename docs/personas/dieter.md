# 다이어터 `dieter`

식단 관리를 하는 사용자다. 끼니 때 앱을 열면 그 끼니를 기록하고, 아침에는 체중을 재고, 저녁에는 가끔 운동을 기록하고, 그 밖에는 홈 화면만 본다(`personas/dieter.py`).

## 프로필

계정 번호로 정해지고 바뀌지 않는다.

- 목표 `LOSE`, BMI 23-29의 키와 몸무게, 활동량은 `SEDENTARY`·`LIGHT`·`MODERATE` 중 하나다.
- 점심·저녁 검색어로 쓸 선호 음식 4개를 `main_keywords`에서 고른다. 아침과 간식은 `breakfast_keywords`에서 고른다.

## 세션 고르기

앱을 연 시각마다 아래 규칙으로 고른다.

| 연 시각 | 실행하는 세션 | 통계 이름 |
|---|---|---|
| 아침 창(06-09시)에서 그날 처음 | 60% 확률로 식사 기록, 아니면 조회 | `dieter_breakfast` |
| 점심 창(11-14시)에서 그날 처음 | 95% 확률로 식사 기록, 아니면 조회 | `dieter_lunch` |
| 저녁 창(17-20시)에서 그날 처음 | 90% 확률로 식사 기록, 아니면 조회 | `dieter_dinner` |
| 간식 창(14-17시)에서 그날 처음 | 30% 확률로 간식 기록, 아니면 조회 | `dieter_snack` |
| 체중 창(06-10시)의 조회 세션 중 그날 처음 | 40% 확률로 체중 기록, 아니면 조회 | `dieter_weight` |
| 운동 창(20-23시)의 조회 세션 중 그날 처음 | 주간 목표 횟수 / 7 확률로 운동 기록, 아니면 조회 | `dieter_workout` |
| 그 밖의 모든 경우 | 조회 | `dieter_view` |

그래서 끼니마다 식사 기록은 하루 최대 한 번이고, 체중 기록과 운동 기록도 하루 최대 한 번이다. 체중 창은 아침 창과 겹치지만 식사 기록이 된 세션은 바꾸지 않는다.
끼니 창과 확률은 `[personas.dieter.meals.*]`, 체중은 `[personas.dieter.body_weight]`, 운동은 `[personas.dieter.workout]`에 있고 값은 모두 가정이다.

운동 창에 앱을 열지 않은 날은 운동하지 않으므로 실제 운동 횟수는 주간 목표보다 적다. 계정 1,000개로 일주일을 계산하면 하루 약 100건, 계정당 주 0.7회 정도다.

## 세션: 식사 기록 `meal_log`

앱을 열고, 음식을 검색해 한 끼를 저장하고, 바뀐 요약을 확인한다(`sessions/meal_log.py`). 한 세션이 약 14초 걸린다.

| 순서 | API | 하는 일 |
|---|---|---|
| 1 | `GET /daily-summaries/{date}` | 홈 화면. 오늘 요약 |
| 2 | `GET /daily-goals/{date}` | 홈 화면. 오늘 목표. 404는 코칭 계획이 없는 것이라 정상으로 본다 |
| 3 | `GET /growth/me` | 홈 화면. 성장 기록 |
| 4 | `GET /meals?date=...` | 오늘 식사 목록. 이 끼니를 이미 기록했으면 여기서 끝내고 `(skipped)`로 센다 |
| 5 | `GET /foods?keyword=...` | 음식 검색. 음식마다 한 번, 한 끼에 2개 |
| 6 | `POST /meals` | 검색 결과에서 고른 음식과 양(100-300g)으로 저장. 201, 같은 내용을 다시 보낸 경우 200 |
| 7 | `GET /daily-summaries/{date}` | 저장 뒤 요약 |
| 8 | `PATCH /meals/{mealId}` | 식사 기록의 15%만. 음식 하나의 양을 0.5-1.5배로 고친다(`edit_probability`) |
| 9 | `GET /daily-summaries/{date}` | 8을 보낸 경우만. 고친 뒤 요약 |

- 1-4는 앱이 자동으로 부르는 조회라 사이에 기다리지 않는다.
- 검색 전에 2-6초(검색어 입력), 결과에서 고르기 전에 1-4초(음식 선택)를 기다린다. `[think_time]`
- 아침·간식은 `breakfast_keywords`에서, 점심·저녁은 계정의 선호 음식에서 검색어를 뽑는다. 결과가 비면 남은 후보로 다시 검색한다.
- 양을 고치기 전에 1-4초를 기다린다. 고칠지와 고칠 양은 계획할 때 정한다.

**검증.** 아래가 맞지 않으면 실패로 센다.

- 저장 응답의 `clientUuid`, `mealType`, 먹은 날짜, 음식 ID와 양이 보낸 값과 같다.
- 저장 뒤 요약의 섭취 칼로리가 저장 전보다 저장한 식사 칼로리만큼(오차 1kcal) 늘었다.
- 고친 경우: 수정 응답의 식사 ID, `clientUuid`, 음식 ID와 양이 보낸 값과 같고, 요약의 섭취 칼로리가 식사 칼로리의 변화만큼(오차 1kcal) 달라졌다.

`clientUuid`는 이메일, 날짜, 끼니로 정해진다. 그래서 세션을 다시 실행해도 같은 끼니가 두 번 저장되지 않는다.

## 세션: 체중 기록 `weight_log`

앱을 열고, 현재 몸무게를 보고, 오늘 체중을 저장한 뒤 최근 30일 그래프를 본다(`sessions/weight_log.py`).

| 순서 | API | 하는 일 |
|---|---|---|
| 1-3 | 홈 화면 3종 | 조회 세션과 같다 |
| 4 | `GET /weight-records/latest` | 현재 몸무게 |
| 5 | `PUT /weight-records/{오늘}` | 오늘 체중. 처음이면 201, 이미 있으면 200이다 |
| 6 | `GET /weight-records?from=..&to=..` | 오늘을 포함한 최근 30일 |

- 5 전에 1-4초(체중 입력)를 기다린다.
- 체중 = 온보딩 체중 + (날짜 - `reference_date`)일 × 하루 -0.05kg ± 0.5kg이다. 흔들림은 계정과 날짜로 정하므로 다시 실행해도 같은 값을 보낸다.

**검증.** 저장 응답과 30일 목록의 오늘 기록이 보낸 날짜·체중(소수 둘째 자리)과 같다.

## 세션: 운동 기록 `workout`

앱을 열고, 루틴과 이번 주 일정을 받고, 끝난 운동 하나를 올리고, 주간 목표를 확인한다(`sessions/workout.py`).
서비스에는 루틴을 직접 만드는 방법(`POST /routines`)만 있고 AI 추천 루틴은 아직 없다(MVP2). 그래서 루틴을 직접 만드는 회원(30%)만 루틴대로 운동하고, 나머지는 루틴 없이 자유 운동을 기록한다. 어느 쪽인지는 계정마다 고정이다.

| 순서 | API | 하는 일 |
|---|---|---|
| 1-3 | 홈 화면 3종 | 조회 세션과 같다 |
| 4 | `GET /routines` | 내 루틴 전체 |
| 5 | `[setup] GET /exercises` | 종목 목록. 프로세스에 사본이 없을 때만 페이지 수만큼 받는다 |
| 6 | `[setup] PUT /weekly-workout-goal/me` | 루틴을 만드는 회원이고 루틴이 없을 때만. 주간 목표(2-3회) |
| 7 | `[setup] POST /routines` | 6과 같은 조건. 루틴 1-2개, 루틴마다 4종목 × 3세트 |
| 8 | `GET /workout-schedules?from=..&to=..` | 오늘부터 7일 동안의 일정 |
| 9 | `POST /workout-schedules` | 루틴이 있고 일정이 비어 있을 때만. 주간 목표 횟수만큼 7일에 고르게 예약한다 |
| 10 | `GET /exercises?bodyPart=..` | 30%만. 부위별 종목 둘러보기(`browse_probability`) |
| 11 | `GET /workout-sessions?from=..&to=..` | 최근 7일 기록. 오늘 기록이 이미 있으면 여기서 끝내고 `(skipped)`로 센다 |
| 12 | `GET /workout-sessions/recent-sets?exerciseIds=..` | 오늘 할 종목의 이전 기록. 앱이 세트를 기록하는 동안 보여 준다 |
| 13 | `POST /workout-sessions` | 끝난 운동 업로드. 201, 같은 내용을 다시 보낸 경우 200 |
| 14 | `GET /weekly-workout-goal/me` | 주간 목표 진행 |
| 15 | `[setup] PUT /weekly-workout-goal/me` | 자유 운동 회원이고 목표가 없을 때만. 처음 한 번 목표를 정한다 |

- 9 전에 1-4초(날짜 고르기), 10 전에 2-6초(부위 고르기), 15 전에 1-4초(목표 고르기)를 기다린다.
- 주간 목표를 루틴보다 먼저 정한다. 준비를 다시 하는 조건이 "루틴 목록이 비었다" 하나뿐이라, 루틴을 만든 뒤 목표 요청이 실패하면 목표가 영영 정해지지 않기 때문이다.
- 루틴 운동은 오늘 일정의 루틴을, 일정이 없으면 계정이 고른 루틴을 수행한다. 오늘 미완료 일정이 있으면 `scheduleId`로 연결하고, 세트의 15%는 건너뛴다.
- 자유 운동은 그날 고른 종목 3개(무게·횟수 2개, 횟수 1개)를 3세트씩 모두 완료로 올린다. 루틴 ID를 보내지 않고 시작 구성은 빈 배열이다.
- 운동 시간은 30-60분이고, 세션을 연 시각에 끝난 것으로 올린다. 세트 완료 시각은 그 사이에 고르게 둔다.
- 목표 무게는 몸무게 × 근력 × 장비 비율 × 부위 비율이다(`target_weight`). 근력은 다이어터 0.6 × 성별(여성 0.65) × 개인차(0.8-1.2)이고 계정마다 고정이다. 남성 80kg이면 바벨 벤치프레스 30kg, 스쿼트 40kg 정도다. 바벨은 빈 봉 20kg 아래로 내려가지 않는다.
- 목표 횟수는 무게·횟수 종목 10-15회, 횟수 종목 15-20회, 시간 종목 30-60초다. 실제값은 목표에 흔들림을 준다.
- `clientUuid`는 이메일과 날짜로 정해진다. 그래서 세션을 다시 실행해도 같은 날 운동이 두 번 저장되지 않는다.

**검증.** 아래가 맞지 않으면 실패로 센다.

- 이전 기록 응답에 요청하지 않은 종목이 없다.
- 업로드 응답의 `clientUuid`가 보낸 값과 같다.
- 루틴 운동 회원의 주간 목표가 정해져 있다.

## 세션: 조회 `view`

홈 화면만 보고 닫는다(`sessions/view.py`).

| 순서 | API | 하는 일 |
|---|---|---|
| 1 | `GET /daily-summaries/{date}` | 오늘 요약 |
| 2 | `GET /daily-goals/{date}` | 오늘 목표. 404는 정상으로 본다 |
| 3 | `GET /growth/me` | 성장 기록 |

**검증.** 요약의 날짜가 요청한 날짜와 같아야 한다.
