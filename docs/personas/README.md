# 페르소나

발생기가 계정마다 어떤 API 흐름을 실행하는지 정리한다. 페르소나마다 파일 하나를 두고, 그 페르소나가 쓰는 세션의
요청 흐름까지 적는다. 페르소나나 세션을 더하거나 바꾸면 해당 파일도 함께 고친다.
숫자 설정값은 `config/default.toml`이 기준이다.

- **페르소나:** 계정의 성격이다. 계정 프로필을 만들고, 앱을 연 시각마다 어떤 세션을 실행할지 고른다. `kkugi_load/personas/`
- **세션:** 앱을 한 번 열어서 하는 일이다. 요청 순서와 결과 검증을 담는다. 여러 페르소나가 같은 세션을 함께 쓴다. `kkugi_load/sessions/`

## 페르소나 목록

| 페르소나 | 상태 | 쓰는 세션 |
|---|---|---|
| [다이어터](dieter.md) `dieter` | 구현. 1,000명 | 식사 기록(수정 포함), 체중 기록, 운동 기록, 조회 |
| [운동 초보자](beginner.md) `beginner` | 구현. 1,000명 | 루틴 운동 주 2-3회, 조회 |
| [하루 몰아 기록형](batch.md) `batch` | 구현. 1,000명 (4,000명 단계) | 23시대 몰아 기록(식사·체중·운동), 조회 |
| [운동 숙련자](expert.md) `expert` | 구현. 1,000명 (4,000명 단계) | 루틴 운동 주 5-6회, 식사 기록, 체중 기록, 조회 |

운동 기록 세션(`sessions/workout.py`)은 여러 페르소나가 함께 쓴다. 요청 순서, 루틴을 만드는 회원과 자유 운동 회원의
차이, 무게를 정하는 방법은 [다이어터 문서](dieter.md#세션-운동-기록-workout)에 있다. 페르소나마다 근력과 횟수 범위만 다르다.
설계는 [결정 기록](../../notes/decisions/2026-10-30-persona-session-expansion.md) 2절에 있다.

## 최종 목표 구성

최종 2만 명까지 계정 수를 2배씩 늘린다(1,000 → 2,000 → 4,000 → 8,000 → 16,000 → 20,000). 기존 계정은 재배정하지
않고, 페르소나마다 예약한 계정 번호 구간 안에서 풀의 `count`만 늘린다. 단계별로 더할 페르소나와 번호 구간은
[결정 기록](../../notes/decisions/2026-11-02-account-ranges-and-ramp.md)에 있다. 지금은 단계 3(4,000명)이다.

워치 유저는 없앴다. 프로젝트에서 워치를 더 이상 쓰지 않는다. 그래서 아래 비율의 합이 85%이고, 최종 비율은 아직
정하지 않았다(확인 필요).

| 페르소나 | 기존 목표 비율 | 행동 |
|---|---:|---|
| 다이어터 | 35% | 끼니마다 식사 기록, 요약·목표 조회 |
| 운동 초보자 | 25% | 루틴 생성 후 주 2-3회 운동 기록 |
| 하루 몰아 기록형 | 15% | 기존 꾸준러. 매일 식사·운동·체중을 23시대에 몰아서 기록 |
| 운동 숙련자 | 9% | 매일 운동, 루틴·일정·이전 기록 활용, 끼니마다 식단 기록 |
| 휴면 직전 | 1% | 드물게 접속 |

## 모든 세션에 공통인 것

### 앱을 여는 시각

일반 접속은 공통 시간대 표로 정하고, 운동 초보자의 주 2-3회 운동 완료 일정은 따로 정한다.
계정은 시간대마다 최대 한 번 앱을 연다. 규칙은 [README 실행 모델](../../README.md#실행-모델).

### 세션 전 준비

세션마다 먼저 실행한다(`sessions/steps.py`의 `ensure_ready`). 이미 준비된 계정이면 요청을 보내지 않는다.

| 순서 | API | 언제 |
|---|---|---|
| 1 | `POST /auth/login/dev` | 토큰이 없을 때 |
| 1 | `POST /auth/refresh` | 액세스 토큰 만료가 120초 안으로 남았을 때. 거절되면 다시 로그인한다 |
| 2 | `POST /members/me/onboarding` | 온보딩 전일 때. 409 `MEMBER_ALREADY_ONBOARDED`는 정상으로 본다 |

통계에서는 이름 앞에 `[auth]`, `[setup]`이 붙는다. 계정마다 처음 한 번 몰리므로, 새 계정을 띄운 직후에 많이 보인다.

### 탈퇴된 계정

어느 요청에서든 401 `MEMBER_WITHDRAWN`을 받으면 그 세션을 끝내고 `ACCOUNT withdrawn`으로 센다. 실패로 세지 않는다.
계정의 generation을 올리므로 다음 세션은 새 이메일로 가입부터 다시 한다.
