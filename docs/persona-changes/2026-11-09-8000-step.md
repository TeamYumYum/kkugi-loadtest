## 바뀐 것

| 항목 | 이전 | 이후 |
|---|---|---|
| 계정 | 4,000명 | 8,000명 |
| 다이어터 | 1,000명 (0-999번) | 4,800명. 추가분 3,800명은 10,000-13,799번 (`dieter-extra-*`) |
| 휴면 직전 | 없음 | 200명, 50,000-50,199번 (`dormant-*`). 가끔 홈만 본다. 계정당 하루 약 0.4회 |
| 노트북 Worker 풀(`peak-*`) | 10,000-11,999번 | 90,000-91,999번 |
| Worker | 8개 | 12개 |
| 실행기(`KKUGI_USERS`) | 360 | 540 |

새 세션은 없다. 휴면 직전도 기존 조회 세션(`view`)만 쓴다. 다이어터 추가분은 기존 다이어터와 같은 규칙(칼로리로 정하는 양, 목표를 지키는 무리)을 따른다.

## 데이터에서 보이는 차이

- **하루 세션과 요청.** 약 2배가 된다. 다이어터 한 명이 하루 약 4.1개 세션을 열어, 추가분이 하루 약 15,600개 세션을 더한다.
- **낮 피크(07, 12, 18시).** 다이어터가 끼니 시간에 몰려 2배보다 조금 더 는다.
- **23시 몰아 기록.** 그대로다(약 18 TPS). 하루 몰아 기록형을 늘리지 않았다.
- **회원 수에 비례하는 backend 작업.** 마지막 끼니 배치(17-24시), 자정 하루 목표 판정, 월요일 주간 리포트가 회원 약 4,054명 -> 약 8,054명을 대상으로 돈다(확인 필요).
- **다이어터 쏠림.** 다이어터가 전체의 60%다. 목표 비율 35%는 다음 단계(16,000명)에서 다른 페르소나를 더해 맞춘다.
- **11-09는 섞인 날이다.** 14:56 이전은 4,000명, 이후는 8,000명이다. 이 날은 비교에 쓰지 않는다.

- **재시작 직후 몰림.** 재시작하는 동안 밀린 세션(늦어도 30분 안이면 실행한다)을 첫 1분에 한꺼번에 실행했다. 14:58 한 분에 요청 2,832건이었고, 그 세션들의 시작 지연은 평균 15분, 최대 29.7분이었다. 실패는 없었다. 발생기를 다시 시작할 때마다 생기는 모양이다.

## 확인 방법

- 계정 번호로 기존 4,000명과 새 4,000명을 나눠 본다. 기존 계정의 달성률 확인([칼로리 변경](2026-11-09-meal-calories.md))은 이 증량과 섞이지 않는다.
- 저녁 배치의 DB 커밋은 하루 요약의 시간대별 DB TPS로 본다. 4,000명 때 17-24시가 초당 약 36-63건이었다.
